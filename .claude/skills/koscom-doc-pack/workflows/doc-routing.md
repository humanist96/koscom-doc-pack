# 문서 형식 라우팅

koscom-doc-pack에서 문서를 만들거나 고치는 요청이 오면 **이 파일을 가장 먼저 읽는다.** 여기서는 출력 형식만 정한다. 형식이 정해지면 그 형식의 담당 파일로 넘기고, 그 뒤의 확인·검증·완료 기준은 담당 파일이 정한다.

**결정권**: 형식 선택은 이 파일이 정한다. `CLAUDE.md`·`AGENTS.md`·각 스킬 설명과 다르면 이 파일을 따른다. PPT 안에서의 경로 선택(새 덱, 템플릿 채우기, 1:1 다듬기 등)은 [`ppt-master/workflows/routing.md`](../../ppt-master/workflows/routing.md)가 정한다.

**먼저 읽지 말 것**: 형식을 정하기 전에는 `ppt-master/SKILL.md`, `koscom-hwp-report/SKILL.md` 같은 담당 파일 전체를 읽지 않는다. 형식을 정하는 데 필요한 것은 이 파일뿐이다.

---

## 1. 원칙

| 원칙 | 하는 일 |
|---|---|
| 정해진 경우는 묻지 않는다 | 2장 표에 맞는 요청이면 질문 없이 바로 넘긴다 |
| 애매할 때만 질문 하나 | 2장에서 "질문"으로 정한 경우에만 3장의 질문을 **한 번** 한다. 답을 받기 전에는 담당 파일을 읽지 않는다 |
| 형식 단어가 문서 종류보다 앞선다 | "PPT로 요약보고 만들어줘"는 PPT다. "보고서", "기획서" 같은 문서 종류보다 PPT·한글·hwp 같은 형식 단어를 먼저 본다 |
| 입력 파일과 출력 형식을 구분한다 | 원천 자료(PDF·DOCX·엑셀·.pptx·.hwp)의 형식은 출력 형식이 아니다. 단, "이 양식에 채워줘"처럼 그 파일을 **틀**로 쓰라는 요청이면 그 파일 형식이 출력 형식이다 |
| 지원하지 않는 것은 바로 말한다 | 4장의 미지원 요청은 다른 경로로 돌려 억지로 만들지 않는다. 안 되는 이유와 가능한 대안을 한두 줄로 알린다 |

위에서부터 처음 맞는 줄을 쓴다.

| # | 요청 신호 | 형식 | 넘길 곳 |
|---|---|---|---|
| 1 | 점검·환경·`.pia`·"렌더러가 안 돼"·상류 업데이트 | 운영 | [`koscom-doc-pack/SKILL.md`](../SKILL.md)의 운영 절 |
| 2 | "둘 다", "보고서랑 발표자료", "한글이랑 PPT", "같은 내용으로 두 가지" | 둘 다 | 5장 절차 |
| 3 | PPT, 피피티, 파워포인트, 장표, 슬라이드, 덱, 발표자료, 프레젠테이션, `.pptx` 출력 | PPT | [`ppt-master/workflows/routing.md`](../../ppt-master/workflows/routing.md) |
| 4 | `.pptx` 파일을 주며 채우기·다듬기·노트·애니메이션 | PPT | [`ppt-master/workflows/routing.md`](../../ppt-master/workflows/routing.md) |
| 5 | 한글 파일, hwp, 한/글, 아래아한글, `.hwp` 출력 | 한글 | [`koscom-hwp-report/SKILL.md`](../../koscom-hwp-report/SKILL.md) |
| 6 | 요약보고, 상세보고, 결재(라인), 개조식, 품의, "팀장님/본부장님께 올릴", 결과보고·계획보고·검토보고 | 한글 | [`koscom-hwp-report/SKILL.md`](../../koscom-hwp-report/SKILL.md) |
| 7 | `.hwp` 파일을 주며 "이 양식에 채워줘", "이 한글 파일 고쳐줘" | 한글(미지원) | 4장 |
| 8 | "보고서"·"보고 문서"·"보고 자료"만 있고 형식 단어가 없음 | 한글 | [`koscom-hwp-report/SKILL.md`](../../koscom-hwp-report/SKILL.md). 단 "발표", "미팅·회의에서 띄울", "화면에 띄울"이 함께 있으면 PPT(3번) |
| 9 | 기획서, 기획안, 제안서, 계획서, 소개자료, 사업 소개처럼 두 형식에서 모두 흔한 문서이고 형식 단어가 없음 | 질문 | 3장 |
| 10 | 삽화, 본문 그림, 개념도, 코쇠 그림만 요청 | 삽화 | [`koscom-kosoe-illustrations/SKILL.md`](../../koscom-kosoe-illustrations/SKILL.md) |
| 11 | Word(`.docx`), `.hwpx`, PDF, 엑셀을 출력으로 명시 | 범위 밖 | 4장 |

- 문서와 삽화를 함께 요청하면("코쇠 그림 넣은 보고서") 문서 형식으로 정한다. 삽화는 그 담당 경로 안에서 코쇠 스킬을 불러 만든다.
- 사용자가 앞선 대화에서 형식을 이미 말했다면 다시 묻지 않는다.

## 3. 판단 질문

2장 9번일 때만 한 번 묻는다. 질문 도구(`AskUserQuestion`)가 있으면 선택지로, 없으면 채팅으로 묻는다.

> 어떤 형식으로 만들까요?
> ① 한글 보고서(.hwp, 코스콤 보고 양식) ② PPT(.pptx) ③ 둘 다

- 다른 선택(덱 템플릿, 쪽수 등)을 이 질문에 섞지 않는다. 그런 것은 각 담당의 확인 단계에서 정한다.
- 답을 받으면 2장의 해당 줄(①→5번, ②→3번, ③→2번)로 넘긴다.

## 4. 지원하지 않는 요청

| 요청 | 알릴 내용 | 대안 |
|---|---|---|
| 가진 `.hwp` 양식의 빈칸 채우기 | 한글 양식 채우기는 아직 없다(P4 예정) | 내용을 받아 코스콤 보고 양식으로 새로 만든다. 그 양식 그대로가 꼭 필요하면 사용자가 직접 채운다 |
| 기존 `.hwp` 파일 고쳐 쓰기 | 한글 스킬은 기존 파일을 고치지 않고 새로 만든다 | 파일 내용을 알려 주면(복사·붙여넣기 등) 새로 만든다 |
| `.hwpx` 출력 | 지금은 `.hwp`만 만든다 | `.hwp`로 만들고, 한글에서 다른 이름으로 저장해 `.hwpx`로 바꾸게 안내 |
| Word·PDF·엑셀 출력 | 이 팩은 PPT와 한글을 만든다 | 그 형식을 다루는 다른 스킬이 있으면 그쪽으로. 없으면 PPT·한글 중 하나를 제안 |

## 5. 둘 다 — 같은 내용으로 PPT와 한글

공통 설계도(`doc.json`, P5)가 생기기 전까지는 다음 순서로 한다.

1. **한글 먼저.** [`koscom-hwp-report/SKILL.md`](../../koscom-hwp-report/SKILL.md) 절차대로 내용을 개조식으로 정리하고 `.hwp`를 만든다. 이때 만든 `report.json`이 내용의 기준이 된다.
2. **원고 넘기기.** `report.json`의 장·대제목·항목·표를 마크다운으로 옮겨 `projects/<프로젝트>/sources/<제목>.md`로 저장한다. 원래 받은 자료도 같은 폴더에 둔다.
3. **PPT.** 그 원고로 [`ppt-master/workflows/routing.md`](../../ppt-master/workflows/routing.md)부터 진행한다. 장표는 핵심만 담고, 쪽수는 PPT 확인 단계에서 정한다.
4. **삽화는 한 번만.** 코쇠 삽화를 `projects/<프로젝트>/illustrations/`에 만들고 두 결과에서 같은 파일을 쓴다.

각 단계의 확인·검증은 그 담당 파일의 규칙을 그대로 따른다. 두 결과의 수치·용어가 서로 같은지 마지막에 한 번 대조한다.

| "회의 메모를 요약보고로 정리해줘" | 한글 (6번) |
| "장애 건 보고서 만들어줘" | 한글 (8번) |
| "다음 주 고객 미팅에서 띄울 보고 자료 만들어줘" | PPT (8번 단서 → 3번) |
| "AI 상담 서비스 도입 기획서 만들어줘" | 질문 (9번) |
| "같은 내용으로 보고서랑 발표자료 둘 다" | 둘 다 (2번) |
| "이 공모전 신청서 hwp에 내용 채워줘" + `.hwp` | 한글 미지원 (7번 → 4장) |
| "PPT로 요약보고 만들어줘" | PPT (3번, 형식 단어 우선) |
