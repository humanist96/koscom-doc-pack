# 이슈·장애 보고

장애·사고·민원처럼 "일이 터진" 것을 보고할 때 쓴다. 읽는 사람이 가장 먼저 알고 싶은 것은 **무엇이, 언제, 얼마나 영향을 줬고, 지금은 괜찮은가**다.

## 구성

| 대제목 | 쓸 내용 | 라벨 예 |
|---|---|---|
| 발생 개요 | 일시, 대상 시스템·서비스, 현상, 영향 범위, 현재 상태 | (일시) (현상) (영향) (현재) |
| 경과 | 시각 순서 **표**: 발생 → 인지 → 원인 파악 → 조치 → 복구 | |
| 원인 | 직접 원인과 근본 원인을 `-`로 나눔 | (직접 원인) (근본 원인) |
| 조치 결과 | 임시 조치, 복구 확인, 고객 안내 | (임시 조치) (고객 안내) |
| 재발 방지 대책 | 대책별 담당·기한 | (대책 1) |

## 표

- 경과 표: `일시 / 내용 / 비고`(좌우 개방형). 시각은 `14:05`, 날짜가 바뀌면 `10. 27 14:05`
- 재발 방지 대책이 3개 이상이면 `대책 / 담당 / 기한` 표로

## 작성 규칙

- 첫 대제목의 (현재) 항목에 "정상 운영 중", "일부 지연 지속"처럼 지금 상태를 반드시 쓴다
- 확인되지 않은 원인은 "추정", "확인 중"으로 표시한다. 추정을 사실처럼 쓰지 않는다
- 고객사·담당자 실명은 사용자가 준 표기대로 쓰고, 예시·시험에서는 `A사`처럼 쓴다
- 사과 문구, 책임 소재 판단은 사용자가 요청할 때만 넣는다
